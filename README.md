# 聚水潭查询服务

服务通过 Flask 提供库存、虚拟库存和采购入库查询，由 Gunicorn 26.0.0 的自定义线程 worker 接收 HTTP/1.x 请求。服务监听 5011，支持公网 IP 加端口以及 Traefik HTTPS 域名入口，业务接口使用统一鉴权。

## 客户端读取期限

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| HTTP_HEADER_READ_TIMEOUT | 10 秒 | 每次请求在线程中开始处理后的请求头读取期限 |
| HTTP_BODY_READ_TIMEOUT | 30 秒 | 请求头解析完成后的请求体读取期限 |

配置必须为有限正数。期限按单调时钟计算，连续零星发送数据不会延长期限。超时关闭客户端连接，并记录 `client_read_timeout` 日志，包含阶段和来源地址。该 worker 用于明文 HTTP/1.x；TLS 在 Traefik 终止。

请求体应在业务处理前读取完整。期限只在客户端套接字收包时检查；完整请求后的聚水潭查询、分页、重试及响应生成可以超过这些期限。聚水潭调用仍使用业务请求的 `timeout` 参数，保持原有默认值与重试策略。Gunicorn 的 `timeout=420` 是 worker 存活监控参数，不能当作单个请求的总耗时限制。

服务采用一个 worker 和八个线程，共享进程内令牌及刷新锁。读取期限可以清理残缺请求造成的线程占用；若所有线程正在处理正常的长耗时业务，其他请求仍可能排队。依赖版本升级时需运行 TCP 回归测试，验证 worker 与 Gunicorn 的请求解析生命周期兼容。

## 健康检查与验证

镜像每 30 秒访问一次本地 `/health`，连续三次失败标记为 unhealthy。Docker 的健康状态用于观测；`restart: unless-stopped` 只处理进程退出，不会因为 unhealthy 自动重启。

`/health` 的常规访问日志被过滤；业务接口的访问日志、异常堆栈和客户端收包超时告警正常记录。

```bash
uv sync --frozen
uv run python -m unittest discover -s tests -v
```

测试使用本地临时端口及模拟业务，不访问真实聚水潭或数据库。覆盖残缺请求头、持续缓慢发送、固定长度与分块请求体、慢业务处理以及连接复用。
